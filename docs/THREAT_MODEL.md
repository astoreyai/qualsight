# QualSight threat model and local data controls

Scope: a single researcher's controlled workstation holding face images and derived biometric data
(quality measures, embeddings, comparison scores). QualSight is a local tool with no accounts or cloud
component. It runs a loopback HTTP server for its browser console and API, but exposes no remote or
shared service.

## Assets

1. Source images (LFW funneled release; the OFIQ conformance image) — owned by the researcher under
   the recorded use decisions; QualSight reads them at their registry paths and never copies them
   into its records, reports (unless the image policy explicitly permits and the classification is
   PUBLIC/PRIVATE), bundles, or exports.
2. Derived biometric data — embeddings, comparison scores, quality measures (classification
   `SENSITIVE_BIOMETRIC_DERIVED`), analysis documents, figures, reports.
3. Provenance records — the append-only SQLite store (projects, Runs, audit events, artifacts).
4. Registered runtimes and models — OFIQ v1.1.2, matcher checkpoints, SCRFD; identified by hash.

## Adversaries and controls

| Threat | Control | Evidence |
|---|---|---|
| Runtime exfiltration of images or derived data over the network | The control plane binds `127.0.0.1` only. API and CLI startup install the process-wide network guard unless `QUALSIGHT_NETWORK_GUARD=0` explicitly disables it; it refuses and counts non-loopback TCP connections and UDP datagrams. Operator-requested dependency pulls enter a thread-bounded setup scope. Architecture, checkpoint, and verification-dataset pulls use registered hash-pinned sources; downloaders disable environment proxies, fix HTTPS origins and redirect hosts, bound response metadata/bytes, and verify exact registered size/SHA-256 before installation. Scientific jobs never acquire dependencies implicitly. `/api/health` reports guard state and attempt counts. | `scripts/audit_local_data_controls.py` (static posture check), `scripts/offline_gate.py` (full workflow under the guard with zero refused attempts), backend tests `test_network_guard_refuses_non_loopback_and_admits_loopback_in_a_fresh_process`, `test_real_cli_assessment_installs_the_default_network_guard`, and `test_checkpoint_acquisition_real.py` |
| A checkpoint endpoint, proxy, redirect, or local file race installs unregistered executable model bytes | The acquisition manifest is a closed six-resource contract. Every checkpoint requires an explicit owner-approved local-noncommercial scope; factual license states remain visible and redistribution is prohibited. The downloader bypasses environment proxies, permits only the exact published HTTPS file and recorded redirect chain, requires pinned content headers, streams to a private partial file with a one-GiB ceiling, verifies exact length/SHA-256, promotes by no-clobber hard link, refuses symlinks/drift, and rolls back a newly installed inode if its durable receipt cannot be published. Lifecycle mutation holds the runtime manager's exclusive-control lock through completion-event persistence or rollback, so a scientific lease cannot use newly installed bytes before the event becomes durable. | `resources/manifests/matcher-checkpoint-acquisition-v1.json`; `qualsight/matchers/acquisition.py`; `MatcherRuntimeManager.exclusive_control`; backend `test_checkpoint_acquisition_real.py` and `test_matcher_lifecycle_real.py` |
| A downloaded verification archive writes unexpected paths, survives without completion evidence, or silently supplies fabricated identities | The one closed archive contract pins its exact HTTPS endpoint, headers, byte length, and SHA-256. Extraction writes only regular `img.list`, `pair.list`, and numbered JPEG members beneath the three registered protocol directories; absolute paths and traversal are refused, while every out-of-contract archive member is ignored without extraction. Required-member type, count, pair-label, and list-hash drift are refused. READY requires a durable exact receipt. Failure to persist or publish the completion event withdraws that receipt and removes only bytes introduced by the request; verified pre-existing bytes remain. The datasets are explicitly pair-only and expose no identity count. | `resources/manifests/verification-dataset-acquisition-v1.json`; `qualsight/dataset_acquisition.py`; `GET /api/addons` |
| An add-on manifest executes arbitrary code or bypasses the Python network guard through a child/native process | The catalog is a closed allowlist of code-owned driver identifiers. It has no module path, package, command, hook, or executable field and no generic loader. Matcher/preprocessing selection is declarative and resolved only through frozen enums and leaf identities. | `qualsight/addons.py`; backend test `test_closed_addon_catalog_contains_only_real_admitted_capabilities` |
| A remote API connector receives images, embeddings, or credentials without a governed data flow | No API connections are admitted in the beta catalog. The catalog returns an explicit policy requiring approved data flow/classification, secrets handling, endpoint pinning, egress control, and immutable Run provenance before a local adapter can be admitted. Imported external score files remain inert, locally registered artifacts marked `EXTERNALLY_COMPUTED`; they are not connectors. | `GET /api/addons`; backend test `test_closed_addon_catalog_contains_only_real_admitted_capabilities` |
| Cross-site requests or DNS rebinding drive the unauthenticated loopback control plane | Every HTTP request requires an admitted loopback `Host` (`127.0.0.1` or `localhost`); state-changing browser requests that carry `Origin` are refused unless scheme, hostname, and effective port exactly match that request Host. Non-browser local clients without `Origin` remain supported. This is a local single-user boundary, not multi-user authentication or authorization. | backend tests `test_local_browser_boundary_refuses_cross_site_mutation_and_dns_rebinding` and `test_figures_dashboards_reports_exports_and_reproduction_bundles_on_the_real_fixture` |
| Secrets (tokens, credentials) leaking into records or logs | QualSight stores no credentials. The audit script scans every stored record, the ledger, and every text file under the data directory for the values of credential-like environment variables and common token shapes. | `scripts/audit_local_data_controls.py` → `LOCAL_DATA_CONTROLS_OK` |
| Another local account reads biometric records through permissive filesystem modes | Process startup activates umask `077`, refuses filesystem roots, protected ancestors, symlinks, or special nodes as the managed data tree, and remediates admitted directories to `0700` and regular files to `0600` before opening the store. This is file-permission isolation, not encryption at rest. | `qualsight/security/local_storage.py`; backend tests `test_existing_application_tree_is_remediated_to_private_modes`, `test_new_application_files_inherit_private_mode`, `test_filesystem_root_and_protected_ancestors_are_refused_before_traversal`, and `test_symlink_inside_application_tree_is_refused` |
| A compressed owner image exhausts decoder memory before the pixel limit is checked | Upload bodies are streamed to a 64 MiB ceiling. Before OpenCV allocates a pixel plane, admission parses bounded JPEG, PNG, BMP, or PPM header dimensions and refuses images above 96 megapixels; after decode, the dimensions must equal the encoded header. Other formats are not admitted. | `qualsight/importers/owner_supplied.py`; real registered JPEG/PNG header-to-decode regression `test_owner_image_header_real.py`; streaming regression `test_upload_streaming_real.py` |
| Unattributed or cross-project scientific actions | Every meaningful action (project lifecycle, dataset import, engine and matcher Runs, analyses, figures, dashboards, reports, exports, bundles, reproductions, annotations, purges) writes an audit event with the configured user (`QUALSIGHT_ACTOR`, default `local-user:<login>`) and a timezone-aware timestamp; `GET /api/projects/{id}/audit`. Annotation subjects use a closed project-owned resolver, and annotation plus audit commit atomically. | backend tests `test_zz_audit_attribution_and_verified_purge` and `test_annotation_integrity_real`; offline gate step `audit-attributed` |
| Tampered inputs, models, uploads, or bundles | Registered artifacts are hash-pinned; readiness re-hashes the OFIQ binary and configuration; adapters refuse unregistered runtimes and drifted bytes; bundles carry `checksums.sha256` and reproduction refuses (BLOCKED) on mismatch. Owner uploads stage to a private file, fsync, publish by no-clobber hard link, and revalidate the exact regular-file bytes before recording; drifted or symlinked content-address targets are refused. | registry validators; readiness and owner-admission hardening tests; reproduction test with a tampered bundle |
| Crash between artifact publication and SQLite/audit completion | Scientific and reporting mutations bind a durable operation/request identity to privately staged, fsynced, no-clobber output; startup or same-request retry reconciles only exact receipt membership and hashes. Partial, foreign-project, symlinked, or malformed stages are refused and included in purge discovery. | real SIGKILL, SQLite-abort, prepared-output integrity, reporting-recovery, and partial-purge tests |
| Pair-generation memory or output exhaustion | Owner protocols preflight identity counts, refuse above 20,000 source samples or 20,000 output pairs, and sample deterministic pair ranks without constructing the quadratic candidate set. API work is admitted through bounded capacity. | real LFW owner-pair preflight and bounded-capacity tests |
| An independent verifier disrupts the live SQLite WAL/SHM lifecycle | Child processes never open the API-owned live database while the API owns it. `qualsight snapshot-database` holds the exclusive data-directory lease while `RunStore.snapshot_database` uses SQLite's Backup API under the writer lock, verifies the copy, and publishes it privately with no-clobber semantics. Independent verification/audit processes require the named snapshot contract and open it read-only and immutable. A default local-data audit acquires the same exclusive lease or refuses to inspect the live database; its snapshot mode still scans the real managed files. | ADR 005; ordered real API regression `test_cross_matcher_contrasts_hold_identities_fixed_and_resolve_disagreements_to_pairs` binds live WAL/SHM inode identity and `test_zz_audit_attribution_and_verified_purge` audits a consistent snapshot before purge; `test_database_snapshot_cli_and_independent_audits_fail_closed` executes the CLI snapshot and lease refusal paths against the real store |
| A partial schema change claims the current version and is repaired without rollback evidence | Startup accepts a current `PRAGMA user_version` only when the exact ordered migration ledger and every required table, foreign-key, and index structure match the declared schema. Any current-version inconsistency receives the same private, integrity-checked, no-clobber preflight snapshot as an older schema before reconciliation begins; migration failure restores that exact snapshot. | `RunStore._migration_snapshot`; real regression `test_incomplete_target_ledger_is_snapshotted_and_restored_before_schema_repair` and the complete `test_operation_recovery_real` module |
| A UI or API request names an ambiguous subset of matcher/preprocessing leaves | The verification endpoint accepts only a complete matcher × preprocessing Cartesian product, rejects unknown or non-Cartesian leaf sets, and records the exact selection rule in the matrix evidence. | backend test `test_matrix_rejects_a_non_cartesian_addon_selection`; browser observation records the catalog-backed selector state |
| A cross-site navigation, prefetch, or image request triggers export creation | Export creation is POST-only and passes the loopback API's exact scheme/host/port Origin check before entering the project purge fence. The receipt's GET route can only verify and serve an already-created project-owned prepared output; retired GET creation requests return 404 and leave the export tree unchanged. | real LFW reporting/export regression `test_figures_dashboards_reports_exports_and_reproduction_bundles_on_the_real_fixture`; release browser audit downloads and hashes the CSV attachment |
| Residual data after a study ends | Application-level verified purge: `POST /api/projects/{id}/purge` (confirmation must repeat the project id) atomically excludes new state-changing project requests and refuses active in-process work, deletes every managed sample copy and derived artifact file recorded for the project, re-verifies absence, then deletes and verifies the corresponding sample/result/embedding/comparison/analysis/report metadata. Content-addressed owner inputs retain per-project references; a process-wide owner-file mutation lock excludes admission while purge selects and unlinks files, and shared bytes are removed only after the final reference. Only the project/version shell, audit history, and purge attestation remain; source images outside QualSight are never touched. **Not performed:** secure erasure of SQLite free pages, filesystem journals, or backups — those are outside the application and must be handled by the workstation's own controls. The data-directory OS lease admits exactly one API or CLI writer process, so a second process is refused before it can bypass the owner-file guarantee. | `qualsight/security/purge.py` (`SCOPE_STATEMENT`), `qualsight/security/owner_file_lock.py`, `qualsight/security/process_lease.py`, `RunStore.purge_project_records`, backend tests `test_zz_audit_attribution_and_verified_purge`, `test_z_purge_and_real_upload_are_mutually_exclusive_and_leave_no_residual_project_data`, `OwnerFileCrossProjectRaceTests`, and `DataDirectoryLeaseTests`; `GET /api/projects/{id}/purge-scope` |
| Generated report, figure-provenance, or embedding bytes are altered after recording | Report HTML, PDF, JSON, report provenance, and figure-provenance downloads verify the originally recorded file-byte SHA-256 rather than trusting the current path or parsed object. The response is copied from a no-follow file descriptor to a private snapshot, verifies that same open inode before and after the copy, and streams only that snapshot. Legacy figure rows are accepted only when their stored canonical-object hash matches the parsed object and the current bytes match the deterministic renderer output. Embedding inventory re-hashes recorded artifacts and returns `MISSING`, `DRIFTED`, or `INVALID_FORMAT` without parsing untrusted drifted bytes. | backend tests `test_figures_dashboards_reports_exports_and_reproduction_bundles_on_the_real_fixture` and `test_project_embedding_inventory_rehashes_recorded_artifacts` |
| Restricted images reaching outputs | Report images are embedded only under `image_policy=INCLUDE_PERMITTED` and only for PUBLIC/PRIVATE datasets; RESTRICTED sources are never embedded and RESTRICTED records are refused by the exporters; bundles carry paths and hashes only. Report and bundle bytes are explicit project-authorized operator downloads, not path-free browser JSON, and require a disclosure review before external transfer. | report/export code paths and tests |
| Public operational or reproduction responses expose native workstation diagnostics | Readiness failures return stable dependency codes only. Every non-completed purge journal blocks readiness. Reproduction POST/list responses remove dependency locations and native error text while the full record remains in the private local store. | `RunStore.operational_status`; `/api/ready`; `_public_reproduction_result`; backend purge and reproduction tests |

The Python socket guard does not provide OS-level egress control. It intercepts sockets created by the
QualSight Python process and records refused attempts, but it cannot constrain a native executable or
child process that opens its own socket. The controlled beta therefore admits only reviewed, hash-bound
local executables and container work with `--network none`; host firewall and operating-system egress
policy remain deployment responsibilities. This limitation prevents the Python guard from being used as
evidence of DHS network containment.

## Out of scope

Multi-user access control, disk encryption, physical access, and OS hardening are the workstation's
responsibility. QualSight's optional local-account mode (PRD §50) is not required for the beta gate.

Release archives are integrity-addressed, not publisher-signed. The release builder refuses dirty
trees and existing destinations, validates the exact Python/uv/Node/pnpm toolchain before dependency
mutation, extracts the exact commit into private staging, performs a frozen
all-group Python install and a frozen frontend install, rebuilds the console there, derives the SBOM,
vulnerability evidence, and artifact manifest only from that staged tree, and publishes the complete
versioned directory under one release lock with an atomic no-clobber rename. The CycloneDX inventory
separates lock-resolved packages, external governed resources, and blocked native resolution; SHA-256
checksums bind every emitted file. Source creation and extracted-package validation share the same
content-aware boundary: forbidden binary signatures, exact registered restricted artifact hashes,
encoded operator-home values, secrets, special nodes, and prohibited path/name/suffix classes are
refused. The embedded `QUALSIGHT-PACKAGE-CONTENTS.json` binds the expected source commit and every
projected regular file's sorted relative path, SHA-256, byte length, and normalized safe mode. The
committed-tree validator uses no-follow file descriptors and stable before/after identities, refuses
unsafe directory modes, and detects added, removed, altered, redirected, or mode-changed members before
examining their semantics. A hardened extraction umask may safely reduce group/world access while
preserving owner access; added permissions, special bits, group/world write, and modes outside the
archive declaration are refused. Production source maps are disabled; console bytes are scanned for private build paths before
archiving. These controls detect accidental or malicious
byte changes only when the verifier obtains the checksum file through a trusted channel; they do not
provide signer identity or nonrepudiation. The package remains bound to a controlled single-user
workstation because the scientific registry contains deployment-local absolute paths.
